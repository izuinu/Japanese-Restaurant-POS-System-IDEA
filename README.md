# 個人飲食店向け 最小構成レジ・簡易経費管理システム

## 1. 開発の思想・哲学的アプローチ

* **「後で仕事が増えない」先回り設計**
入力時の数秒をケチって適当に記録すると、年末の確定申告（青色申告）で過去1年分を手計算する地獄を見る。入力の手間を増やさずに「確定申告の決算書にそのまま転記できる」状態を日常業務で自動化する。
* **過剰機能の徹底排除**
大手の理論（JIT在庫管理・リアルタイムBOM・自動釣銭機）を個人店に持ち込むのは自滅の元。「何を作らないか（Non-Features）」を強固に定義し、現場のあそび（余裕）を残す。
* **「人間とシステムの泥臭いコラボレーション」**
同じ問屋や買い出しなどで食材（仕入）とポリ袋（消耗品）が混ざる現場のリアルに対し、システムを複雑化するのではなく「納品書や請求書に手書きメモ（人間）＋ 経費画面で2行入力（システム）」という割り切りで解決する。

## 2. システム構成・機能要件

### ① 収入ライン（POSレジ / セルフ食券機）

* **通常レジ UI:** メニュータップ、小計、税計算（10% / 8%）、お釣り計算のデカ表示。
* **セルフ食券モード（カウンター・セルフ店向け）:**
入口のタブレットで客が選択・決済 ➔ 厨房用＆客控えの食券（注文番号入り）をサーマルプリンターから自動発行。ホール接客を簡略化。
* **インボイス対応レシート:** 登録番号（T+13桁）、税率別（10%/8%）の対象額および消費税額を自動計算・印字。
* **ドロアー連動:** プリンターのDK（Drawer Kick）ポート経由で会計時に自動開錠。

### ② 支出ライン（現場に即した簡易経費管理）

* **青色申告直結のテンキーUI:**
レシートや納品書を見ながら金額を打ち込み、勘定科目ボタンを選ぶだけの高速入力。
* **伝票の明細行追加（混在対応）:**
1枚の伝票で食材と消耗品が混ざっている場合、「行を追加」ボタンで1伝票・複数科目の記帳に対応。
* **税率・インボイスの自動判定:**
科目を選択した時点で、裏でデフォルトの税率（10% / 8% / 非課税 / 不課税）とインボイス区分が自動セットされる。

### ③ 収支集計 ＆ データ出力

* **FLコスト・概算利益ダッシュボード:**
売上に対する「仕入（F）」と「人件費（L）」の比率を一目で把握。
* **確定申告（P/L）CSV出力:**
ボタン一発で勘定科目ごとの年間集計データをCSV出力。会計ソフトや税理士へそのまま渡せる状態にする。

## 3. データベース設計（SQLite：拡張6テーブル）

```
[ Menu ] ───────< [ OrderItem ] >─────── [ Order ] ───────1:1─────── [ Payment ]
 (メニュー)          (注文明細)           (伝票/食券)           (会計/決済記録)

[ ExpenseCategory ] ───────1:N───────> [ Expense ]
  (経費カテゴリマスター)                 (経費/支出明細)

```

1. **`Menu`:** `id`, `name`, `price`, `tax_rate` (8/10), `category`, `is_sold_out`
2. **`Order`:** `id`, `order_number`, `status` (open/paid/cancelled), `created_at`
3. **`OrderItem`:** `id`, `order_id`, `menu_id`, `quantity`, `unit_price`
4. **`Payment`:** `id`, `order_id`, `subtotal`, `tax_8`, `tax_10`, `total_amount`, `payment_method`, `paid_at`
5. **`ExpenseCategory`:** `id`, `category_name`, `default_tax_type` (10%/8%/非課税/不課税)
* *初期データ:* 1.維持費（家賃・保険等） / 2.光熱費 / 3.仕入 / 4.消耗品 / 5.人件費（不課税） / 6.雑費


6. **`Expense`:** `id`, `category_id`, `amount`, `tax_rate`, `is_invoice_qualified`, `paid_at`, `vendor_name`, `memo`

## 4. ハードウェア ＆ インフラ構成

| 項目 | 採用機材 | 特徴・メリット |
| --- | --- | --- |
| **店内サーバー** | ミニPC（N100等） / Raspberry Pi | 店内LAN内でDocker＋SQLite動作。ネット障害時も100%稼働。 |
| **レジ/食券端末** | 安価なタブレット（iPad/Android） | Webブラウザ（HTML/JS）で動作。故障時は別の端末を置くだけ。 |
| **プリンター** | ESC/POS対応 サーマルプリンター | レシート・食券印字 ＆ ドロアー開錠信号の送信。 |
| **キャッシュドロアー** | DKポート接続手動ドロアー | 釣銭機（銭読みメカ）を廃し、詰まりトラブルと導入コストを排除。 |

## 5. 捨て去った機能（Non-Features）と現場の理由

* ❌ **自動釣銭機（銭読み機構）** ➔ 数百万円のコストと紙詰まり頻発の回避。画面にお釣りをデカ表示して手動運用。
* ❌ **リアルタイムBOM・自動在庫追跡** ➔ 歩留まりや仕込みのブレで破綻するため排除。売り切れ時は「SOLDOUT」ボタンで即対応。
* ❌ **チマチマした少額ジャストインタイム発注** ➔ 在庫管理の煩雑化など、配送料コストを小さくするため、日持ちするものは「箱買い・まとめ買い」で配送効率向上。
* ❌ **シフト管理・タイムカード・給与計算** ➔ 法改正対応の保守地獄を避けるため社労士・外部ツールへ切り離し、月額総額のみ「人件費（不課税）」として1行入力。
* ❌ **レシートOCR自動読み取り** ➔ 誤認識の修正ストレスを無くし、1日30秒の固定ボタンテンキー入力で代替。
